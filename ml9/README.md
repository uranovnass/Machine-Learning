# SVM — классификация и сравнение моделей

## Описание

В работе исследуется алгоритм **SVM (Support Vector Machine)** для решения задач классификации.

Работа состоит из двух частей:

- исследование SVM на синтетическом датасете `make_moons`;
- применение SVM для прогнозирования оттока клиентов и сравнение с другими моделями машинного обучения.

Основная задача — изучить работу разных ядер SVM, влияние параметра `C`, подобрать оптимальные гиперпараметры и сравнить качество моделей по метрикам **F1-score** и **ROC-AUC**.

## Используемые библиотеки

- NumPy
- Pandas
- Matplotlib
- Scikit-learn
- XGBoost

## 1. SVM на синтетических данных

Для демонстрации работы алгоритма используется датасет `make_moons` из `scikit-learn`.

Параметры датасета:

- 300 объектов;
- 2 класса;
- шум `0.25`;
- `random_state=42`.

Перед обучением признаки масштабируются с помощью `StandardScaler`.

### Линейное ядро

Сначала используется SVM с линейным ядром:

```python
SVC(kernel="linear", C=1)
```

Линейное ядро строит прямую границу между классами.

### RBF-ядро

Затем используется нелинейное RBF-ядро:

```python
SVC(kernel="rbf", C=1, gamma="scale")
```

RBF позволяет строить более сложные нелинейные границы и лучше подходит для данных в форме двух полумесяцев.

## 2. Влияние параметра C

Для исследования влияния параметра `C` проверяются значения:

```text
0.01
1
100
```

Параметр `C` определяет, насколько сильно модель старается минимизировать ошибки классификации.

- маленький `C` допускает больше ошибок и создаёт более мягкую границу;
- большой `C` сильнее подстраивается под обучающие данные.

Для каждого значения строится отдельная граница решений.

## 3. SVM для прогнозирования оттока

Во второй части SVM применяется к задаче классификации клиентов.

Целевая переменная:

```text
churn
```

где:

- `0` — клиент не ушёл;
- `1` — клиент ушёл.

Идентификатор `subscriber_code` исключается из признаков, поскольку он не несёт полезной информации для прогнозирования.

Данные разделяются на обучающую и тестовую выборки в соотношении **80/20**.

Для сохранения пропорции классов используется `stratify`.

## 4. Предобработка данных

Категориальные признаки:

- `region`;
- `tariff`.

Для них используется `OneHotEncoder`.

Числовые признаки масштабируются с помощью `StandardScaler`.

Все этапы объединяются в единый `Pipeline`.

## 5. Подбор гиперпараметров

Для поиска лучших параметров SVM используется `GridSearchCV`.

Проверяются следующие значения:

### C

```text
0.1
1
10
100
```

### Gamma

```text
0.001
0.01
0.1
1
```

Всего проверяется **16 комбинаций** параметров.

Для оценки используется **ROC-AUC**, а для проверки применяется 5-fold кросс-валидация.

В результате выбирается комбинация `C` и `gamma`, которая показывает лучший результат на кросс-валидации.

## 6. Сравнение моделей

После подбора параметров SVM сравнивается с другими алгоритмами:

- SVM RBF;
- SVM Linear;
- Logistic Regression;
- Random Forest;
- XGBoost.

Для каждой модели рассчитываются:

- **F1-score**;
- **ROC-AUC**;
- **время обучения**.

## 7. Метрики

### F1-score

F1-score учитывает одновременно Precision и Recall.

Метрика особенно полезна для задачи оттока, поскольку важно правильно находить клиентов, которые могут уйти.

Чем ближе значение к `1`, тем лучше результат.

### ROC-AUC

ROC-AUC показывает, насколько хорошо модель различает два класса.

Чем выше значение, тем лучше модель разделяет клиентов, которые останутся, и клиентов, которые уйдут.

## 8. Масштабируемость

Также сравнивается скорость обучения:

- `SVC(kernel="rbf")`;
- `LinearSVC`.

Эксперимент проводится на выборках разного размера:

```text
1000
3000
5000
```

Это позволяет оценить, как увеличение количества данных влияет на время обучения моделей.
